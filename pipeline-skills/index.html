Software-Change Workflow — Sequence

Same model as the operational spec, sized to actually read. Scroll horizontally for the full width; zoom in/out with your browser as usual.

sequenceDiagram
    actor User
    participant RI as Reference Intake
    participant MDS as Model Dataflow Spec
    participant EE as Evidence Extraction
    participant ES as Evidence Set
    participant ER as Evidence Review
    participant TMP as Target Model Proposal
    participant FSD as File Surface Discovery
    participant CP as Change Planning
    participant IMPL as Implementation
    participant VAL as Validation
    participant FL as Fault Localization

    User->>RI: invoke with Change Request + References
    opt no Current Model on hand
        RI->>MDS: invoke against Codebase
        MDS-->>RI: Current Model
    end
    RI-->>User: Reference Set + Current Model

    rect rgba(47,111,106,0.08)
    Note over RI,ER: Evidence Cycle — reused at every later extraction point
    RI->>EE: Reference Set
    EE->>ES: write evidence
    loop until no pending items or conflicts remain
        ES->>ER: statusless entries
        ER->>User: present one pending item
        User-->>ER: status + justification, per evId
        ER->>ES: annotate in place
    end
    end

    User->>TMP: invoke, reads Evidence Set + Current Model
    TMP->>User: propose Target Model
    User-->>TMP: corrections
    TMP-->>User: approved Target Model
    TMP->>EE: Target Model
    Note over EE,ER: Evidence Cycle repeats (as above)

    User->>FSD: invoke, reads Evidence Set
    FSD-->>User: File Impact
    FSD->>EE: File Impact
    Note over EE,ER: Evidence Cycle repeats (as above)

    User->>CP: invoke, reads Evidence Set
    CP-->>User: Change Plan
    CP->>EE: Change Plan
    Note over EE,ER: Evidence Cycle repeats (as above)

    User->>IMPL: invoke, reads Change Plan + Evidence Set
    IMPL-->>User: Candidate Implementation

    User->>VAL: invoke, reads Candidate Implementation + Evidence Set
    alt pass
        VAL-->>User: Workflow Complete
    else fail
        VAL->>FL: Bug Report(s)
        Note over FL: reads upward chain — Candidate Implementation, Change Plan, File Impact, Target Model, Evidence Set
        FL->>ES: write Fault Assessment, suspects marked non-destructively
        ES->>ER: Fault Assessment, exceptional input
        ER->>User: present one suspect item
        User-->>ER: confirmed / rejected + justification
        ER-->>FL: Confirmed Fault Set
        FL->>TMP: re-invoke fix point, wherever confirmed
        Note over TMP,IMPL: cascade forward — every process between the fix point and Implementation re-runs
        IMPL-->>VAL: new Candidate Implementation
    end
